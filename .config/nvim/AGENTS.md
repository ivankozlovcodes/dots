# AGENTS.md

Personal Neovim config (NVIM v0.12+, ~44 plugins). This directory is only the
entry point; the config itself lives in `~/git/nvim.conf.d`.

## Layout

Two repos:

- `~/git/dots/.config/nvim/` (this dir, symlinked from `~/.config/nvim`)
  - `init.lua` - bootstraps `lazy-workspaces.nvim` and points it at `nvim.conf.d`
  - `lazy-workspaces.json` - which workspaces are on/off on this machine
  - `lazy-lock.json` - the live lockfile (generated by lazy.nvim, don't edit by hand)
- `~/git/nvim.conf.d/` (the config)
  - `lua/myconfig/<workspace>/init.lua` - `M.setup()`: options, keymaps, autocmds
  - `lua/myconfig/<workspace>/plugins/*.lua` - one lazy.nvim spec per file
  - `.agents/keymap_philosophy.md` - keymap groups and rules; read before adding keymaps

Plugins are installed in `~/.local/share/nvim/lazy/`. Mason tools in
`~/.local/share/nvim/mason/`.

## lazy-workspaces

[lazy-workspaces.nvim](https://github.com/ivankozlovcodes/lazy-workspaces.nvim)
is the user's own plugin. It calls `lazy.setup()` itself: never add a second
lazy bootstrap. Each workspace is a folder under `lua/` with an `init.lua`;
every `.lua` file in its spec dirs (default only `plugins/`) is loaded as a
lazy.nvim spec. After lazy starts, each active workspace's `M.setup()` runs.

Workspaces in `nvim.conf.d`:

- `myconfig/common` - everywhere: options, generic keymaps, clipboard, core plugins
- `myconfig/personal` - personal machines: LSP, blink.cmp, treesitter, snacks, AI
- `myconfig/experimental` - unified VCS keymaps (`vcs.lua`)
- `myconfig/vscode` - VS Code habits (`<C-\>` vertical split)

Toggle with `:LazyWorkspacesInclude <ws>` / `:LazyWorkspacesExclude <ws>`
(writes `lazy-workspaces.json` here; takes effect on restart). New workspaces
found on disk are auto-included.

`myconfig/common/themes/` is not a spec dir, so files there are not loaded.

## Conventions

- Put a plugin in the narrowest workspace that needs it. Add new plugins as
  `lua/myconfig/<ws>/plugins/<name>.lua` returning a single spec (`:Install
  <ws> <author/plugin>` scaffolds one).
- Lazy load where possible (`event`, `cmd`, `keys`, `ft`).
- Leader is `<Space>`. Follow `.agents/keymap_philosophy.md`; check for an
  existing mapping (`:verbose map <lhs>`) before adding one.
- Format Lua with `stylua` (conform runs it on save). Indentation is mixed
  (tabs in `init.lua` files, 2 spaces in most specs): match the file you edit.
- Clipboard: `wl-copy` on Wayland, `xclip` on X, OSC 52 otherwise (ssh).

## Commits

- `nvim.conf.d`: one atomic commit per fix, `type(scope): summary`, body, then
  trailers `Agents:\n  - author: <session id>`, `Tested: manual`, `SCRY=nvim`.
- `dots`: changes to these three files. `lazy-lock.json` updates land here, not
  in `nvim.conf.d` (its copy there is stale).

## Debugging

Run headless checks with `-i NONE` so shada is not written. Headless startup
runs the full config (lazy-workspaces sync, treesitter installs).

```sh
# startup messages / errors
nvim -i NONE --headless -c 'redir! > /tmp/msgs | silent messages | redir END' +qa; cat /tmp/msgs
# where a mapping / option was set
nvim -i NONE --headless -c 'redir! > /tmp/v | silent verbose nmap <leader>gg | redir END' +qa; cat /tmp/v
nvim -i NONE --headless -c 'redir! > /tmp/v | silent verbose set tabstop? | redir END' +qa; cat /tmp/v
# eval Lua
nvim -i NONE --headless -c 'lua io.stdout:write(vim.inspect(vim.tbl_keys(require("lazy.core.config").plugins)))' +qa
# timing, health
nvim -i NONE --headless --startuptime /tmp/st +qa
nvim -i NONE --headless -c 'checkhealth' -c 'w! /tmp/health' +qa
```

Some errors only show in a real terminal (UI plugins, noice). If headless is
clean, ask the user for `:messages`.
